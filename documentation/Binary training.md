# Binary tagging: training and application. 

This manual describes the full process used to create and apply multilple binary tagging (bintag) models that determines the usability of an image of a car on manually labeled training data generated by the Flask Angle tagger. The work is split across two notebooks which must be run in sequence due to their interdependencies. First training must be done using: `notebooks/machine learning notebooks/1 - usability tagger.ipynb`, then the best models from there are selected and applied to the dataset using `notebooks/model appliers/1 - apply_bintag.ipynb`. 

Only start this phase once you have manually tagged a few thousand images (FlaskTagging.md); try to get about 400 images per angle, the more the better and after you have generated all bounding boxes for your images. 

## Training phase: 
Goal is to train and evaluate a bunch of CNN models as binary taggers. The evaluation also looks at how well each model is capable of pulling apart the binary classes as more data is fed into the system (fractionplots). This notebook gridsearches over a bunch of parameters to make the binary classifier - it is, admittedly, not the greatest way of doing but it gets the job done. This gridsearch over a bunch of parameters, include a data-fraction (i.e. it'll train on 5% of the data, then 15.5%, 26.1%.... until it trains on the whole tagged traindataset), as a result, it produces quite a lot of models (600); an in-depth comparison is not done here. The reason we look at fractions is to assess if there's enough data or if there's more to be gained by adding more tags. If there's noticeable improvement in the fractionplots of a model from 89.4% to 100%, then the model was trained on sufficient data. If the middle of the two subplots of the fractionplots clear up further for those two fractions, then the model might have benefitted greatly from more data. This assessment is done visually. After selecting models based on standard metrics. 


## Post-training
After training several visualisations and metrics give insight in the performance of the models, given the large number of models, the focus is on sortable metrics. Interesting to see in this evaluation was that cropping systematically resulted in slightly lower metrics than using the full image. A possible reason for this might be that images where a car was cropped off was flagged as unusable. Since the bounding boxes generated by YOLO crop in the image (sometimes too far), it might have picked up on this and started to tag images that are too far cropped in as unusable. (Although, some images that the model flags as usable are still cropped in too far). (YOLO boxes do not focus on completely marking the object, they just want to confidently mark an area of an image.). The cutoff point fo the binary classifier was also evaluated at different points. 

## Full re-training
Three models are finally chosen based on queries and are logged in a CSV file chosen_models.csv; the selected models are then retrained on the full tagged dataset and saved. These models are not all that great by any stretch of the immagination; F1 scores are in the low 90s.

## Post re-training
after retraining the three models based on their best performance are retrained on the whole dataset of manually tagged datapoints. The models are then applied in `notebooks/model appliers/1 - apply_bintag.ipynb`.


# Binary tagging: Applying best models

**IMPORTANT NOTICE**: the csv output will choose three models; whereas the applying notebook will evaluate four. The extra model was a remnant from an earlier version of the code that hadn't automated this task; given the long time it takes to compute for 15.6million images the output was kept. To rectify this you can simply add another model to the finally-chosen csv file by adding a query for it. 

This section of the documentation describes the content of `notebooks/model appliers/1 - apply_bintag.ipynb`; it should be run after completing `notebooks/machine learning notebooks/1 - usability tagger.ipynb`. 

This notebook will connect to the database, fetch all images and process them in batches of 5000 images. The output of this notebook is a new table in MYSQL called `bintag_predicts` with five columns (the image ID (int) and four model scores (floats)). This process can be interrupted at any time, to continue tagging, just relaunch the notebook. 

After applying each model a bunch of visualisations are made to show how it affects the data. Ideally we want the binary classifier to be piling up on the side with low frequencies in the middle valley. That means the model is highly capable of dividing the data in two catageroies with little doubt about the decisions it makes. 

There are cases where our models do not agree and the difference can be extremely high, we use `plot_discord()` to visualize the usability-assesment of each model and the image to try and see a pattern. If there's a clear pattern, we could remove one of the models or retrain it. There was however not clear pattern to be found. Sometimes an image is clearly cut off and not sufficiently marked as 'bad', or it sees an interior and there's still one model that is convinced it's useful. We see however that it is rarely the case that ALL models make the same mistake.

most of the times, the models where in agreement (low discord), we see in the subsection labeled 'Intermodel confusion'. This section visualizes the distance between the lowest and highest score for each image. A low distance as shown in the boxplot means that there isnot a lot of confusion between the models. A difference of ca. 0.4 is already considered an outlier. The mean distance is 0.1412.

Finally we simulate the evolution of the dataset for a cutoffpoint between 0 and 1 per 0.01 increment for the four models. We let the simulation report the amount of usable images that would give us 1% of false positives (so 1% of the outputted data is considered to be an unusable image'). Targetting this 1% results a high false negative ratio (assessing a good image as bad); however even the worst model still ends upwith 3.6 million images. 

The binary tagging phase is far from perfect, but it still leaves us plenty of data to use for brand classificiation. If you combine all models and set a restriction that you want at least two of them to have a usability score of 0.9 or higher, then you end up with 3.99 million images. This will be the approach. In the `final plot_images_as_grid()` we see that there are still unusable images passing, even with this approach, however we need to put this in perspective:
- the images shown in that grid are part of the 20000 manually tagged images, of those 20.0000 we had 12639 flagged as unusable and of those 12639 only 46 are let through. Most of these 46 still clearly show the exterior of a car with clear enough features to identify the brand, so it's unlikely this ratio of 0.36% will cause trouble further down the line. I know this 0.36% is an underestimate (as we're now seeing how good the model is working on the data it was trained on). But we saw in the learning notebook that the F1-score is still in the low 90s for each of the selected models. Furthermore these 46 cases even include images that are tagged unusable for no good reason - i.e. human error.
